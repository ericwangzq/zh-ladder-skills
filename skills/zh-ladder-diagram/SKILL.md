# 中文讲解图

目标：读者看一眼图，就抓住一个结论；再看细节，每条线都能对回原文。

图比文字更容易让人信，所以也更容易误导：一条没有依据的箭头，看起来就像事实。下面的规则一半是为了好看，一半是为了不撒谎。

先读底线规则：`${CLAUDE_SKILL_DIR}/references/底线.md`。

## 用法

本 skill 只在用户手动调用时运行（`/zh-ladder-diagram`，pi 里是 `/skill:zh-ladder-diagram`）。命令后面的文字就是任务；要画的内容（文件路径或粘贴的文字）没给就先问一句，不要自己找。

## 1. 先决定要不要画

只在内容有结构时画：分支、循环、多方之间来回、先后顺序、层级、两个维度上的位置。下面这些情况不画，用文字或表格：

- 三项以内的并列内容
- 一条直线的步骤，用编号列表就够
- 多个对象在同一组指标上比较，用表格
- 一组数字的趋势或比较，那是数据图表，不归本 skill

决定画之后，按问题选图型，见 `references/选图.md`。

## 2. 定下这张图要说的一句话

先写出图的标题：**一句结论，不是主题**。「只有灰度通过的版本才进生产」，而不是「发布流程」。写不出这句话，说明还没想清楚要画什么，或者内容不适合画图。

## 3. 画

默认手写 SVG，因为中文的换行和字体只有手写才完全可控。规范见 `references/中文SVG规范.md`，起手可以复制 `assets/模板.svg`。要点：

- **字体栈固定**：`"PingFang SC","Noto Sans CJK SC","Microsoft YaHei",sans-serif`。
- **框宽按字算，宁宽勿窄**：一个汉字占一个字号宽；13px 字号一行超过约 14 个汉字就手动换行。SVG 不会自动换行，每一行都要你断。
- **最多 12 个节点**。更多就拆成两张图，或者把下一层交给表格。
- **每条箭头写动词或关键数值**，写在线旁边，不压在线上。
- **原文没有的节点和连线不画**。原文说得不确定的关系，用虚线并在标签上加「？」，图下说明。
- **颜色最多三种含义**：一种强调色留给读者最该先看的那个元素；红、绿只在表示「风险/不通过」「通过」时用，并且要有图例。颜色多了，读者就分不清哪个是重点。
- **用户只要一张图、但内容既有结构又有顺序时**，可以在一张图里分两到三个区块，用 ①② 编号，每块有自己的小标题。区块之间用细分隔线隔开。

用户明确要 Mermaid，或者图很大、需要后续频繁改结构时，改用 Mermaid，配置见 `references/Mermaid兜底.md`。

## 4. 检查

1. 运行检查脚本，它会在 Chromium 里按真实字体量每一段文字，报出溢出、文字互相压住、超出画布、省略号截断，并导出 PNG：

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/svg_check.py 图.svg --png 图.png
   ```

   第一次在一台机器上用，先跑 `python3 ${CLAUDE_SKILL_DIR}/scripts/doctor.py` 确认浏览器和中文字体可用。

2. **打开 PNG 自己看一遍**。脚本查不出这些：中文是不是方块、箭头或连线是不是穿过了别的框和文字、编号圆点是不是压在框线上、整体是不是太挤、强调色是不是落在了对的地方。
3. 对照原文核对：图里每个节点、每条线、每个数字，原文里都找得到吗？「可能」「预计」在图里还在吗？

没法渲染时（没有浏览器），直说「未渲染检查」，不要说「看过了」。

## 5. 交付

交付 SVG（可编辑）和 PNG（可直接贴）。图下面用一两句话写读法：先看哪里、虚线和「？」是什么意思。图里塞不下的说明，放在这里，不要缩小字号硬塞进图。

如果一张图仍然遮住了读者要判断的东西（比如他需要改一个参数看结果），用一句话提议用户改用 `zh-ladder-page` 做成交互讲解页。
