# h10 交付说明

这页帮领导看清「同时用的人一多为什么会排队、加一张卡能缓解多少」：先拖「同时在用的请求数」看处理/排队各几个，再切「2 张卡」；默认停在试点高峰（26 个请求、9,000 token），按原文推算约 8 个排队，加卡（两卡各跑一份模型，理论推算）后为 0。排队要等几秒原文没给算法，页面只列实测值并标「原文未说明」；「高峰变慢主要是排队」是推断、未经生产日志验证，页面照此标注。

## 手算核对

1. 高峰：26 个请求、9,000 token、1 张卡：容量 = 170,000 ÷ 9,000 = 18.9 → 18；排队 = 26 − 18 = 8。加卡：18 × 2 = 36 ≥ 26 → 排队 0。页面显示 8 / 0。✔
2. 门槛点：8,000 token、1 张卡：容量 = 170,000 ÷ 8,000 = 21.25 → 21（原文「约 21 个」）。21 个请求 → 0 排队；22 个 → 1 排队；30 个 → 9 排队，页面同时高亮实测行「11.6 秒，是」。另与压测表对照：8,000×20 无排队、32,000×5 无排队、32,000×10 排队，页面结果都一致。✔
