# 分镜

分镜表是给人确认的，分镜 JSON 是给脚本用的。两者内容一样，先写表给用户看，确认后再转成 JSON。

## 结构

| 部分 | 时长 | 内容 |
| --- | --- | --- |
| 标题卡 | 4–6 秒 | 一句话：这个视频讲什么、看完能回答什么问题 |
| 正文镜头 | 3–6 个，每个 15–40 秒 | 一个镜头只讲一步或一个概念 |
| 总结卡 | 6–10 秒 | 三条以内的要点，加上「哪些是推算、哪些未确认」 |

整片控制在 1 到 4 分钟。超过 4 分钟，读者很难看完，通常说明内容该拆成两个视频，或者改用交互页。

## 每个镜头写什么

| 字段 | 写法 |
| --- | --- |
| 旁白 | 口语、短句、一句一个意思。数字照原文，「约」「预计」不能丢。不要说「如图所示」，直接说图里是什么 |
| 画面 | 动画怎么动：出现什么、移动到哪、高亮哪个 |
| 屏幕文字 | 屏幕上出现的关键词和数字，每行不超过 14 个汉字；和旁白说的是同一件事 |
| 依据 | 这个镜头的内容在原文哪里；推算的标「推算」 |

## 语速

中文旁白按配音的真实时长排动画，不要估。分镜阶段需要粗估总时长时，按每秒 4 到 5 个字算，再加上镜头之间的停顿。英文模板里「每分钟 100 词」的参数对中文不适用。

## 分镜 JSON（给脚本用）

示例见 `assets/分镜示例.json`。字段：

```json
{
  "title": "并发一高为什么会排队",
  "tts": { "provider": "edge", "voice": "zh-CN-XiaoxiaoNeural", "rate": "+0%" },
  "gap_seconds": 0.6,
  "scenes": [
    {
      "id": "s01",
      "kind": "title",
      "narration": "为什么并发一高，回答就要排队？",
      "visual": "标题淡入",
      "on_screen": ["并发一高为什么会排队"],
      "basis": ""
    }
  ]
}
```

`kind` 取 `title`、`body`、`recap`。`id` 要唯一，脚本用它给音频文件命名，动画代码也用它取时长。
